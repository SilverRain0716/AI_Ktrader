# Phase 0 — 실측 검증 체크리스트

조사만으로는 확정할 수 없어 **직접 확인해야 하는 항목**들이다. 여기가 채워지기 전에 Phase 1 코드를 쓰지 않는다. 문서 조사와 실제 동작이 다른 지점이 반드시 나오고, 그 차이가 아키텍처를 바꾼다.

항목은 **35개**다 — A 5 · B 5 · C 8 · D 6 · E 5 · F 6.
각 항목은 확인 후 `결과` 칸에 **날짜와 실측값**을 적는다. "될 것 같다"는 기록하지 않는다.

잴 수 있는 것은 손으로 적지 않는다 — `python scripts/phase0_probe.py` 가 자동으로 재서
[`phase0-results.md`](phase0-results.md) 에 회차별로 남긴다. 키움 항목은 앱키가 있어야
하므로, 없으면 `SKIP` 으로 기록하고 나머지를 계속 잰다. **"키가 없어서 아무것도 못 쟀다"가
아니라 "무엇을 못 쟀는지"가 남아야 한다.**

주문(F)은 자동화하지 않는다. 모의투자라도 주문은 사람이 직접 내는 행위다.

REST 문서에는 OpenAPI+의 "10개 제한", "100종목 제한"이 **명시돼 있지 않다.** 백엔드가 같으므로 동일할 가능성이 높지만 근거가 없다.

## 이 결과가 바꿀 수 있는 것

| 실측 결과 | 아키텍처 영향 |
|---|---|
| D2 분봉 깊이가 짧다 (당일치뿐) | 분봉 백테스트 포기 → 일봉 기준 스윙으로 고정. 분봉은 오늘부터 적재 시작 |
| **D2 실측(네이버): 6거래일·OHLC 없음** | **소급이 불가능하므로 이 항목만 마감이 있다.** 오늘 적재하지 않은 하루는 영구 결손이다. 다만 네이버로 쌓을 수 있는 것은 종가와 누적거래량뿐 — 분봉 고저가 필요한 지표는 키움 앱키 이후에만 가능하다 |
| C2/C3 제한이 OpenAPI+와 동일 | 조건식을 소수의 광의 센서로만 운용. 세밀한 스크리닝은 전부 자체 계산 |
| C5 편입 신호 지연이 크다 | 조건식을 진입 트리거로 쓰지 않고 관심 신호로만 사용 |
| E1 네이버가 해외 IP를 막는다 | 데이터 수집을 국내 서버에 두거나 키움 REST로 일원화 |

| A5 리눅스에서 문제 발생 | 실행 계층만 로컬 Windows에 두는 하이브리드로 회귀 |
