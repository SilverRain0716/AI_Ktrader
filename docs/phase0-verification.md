# Phase 0 — 실측 검증 체크리스트

조사만으로는 확정할 수 없어 **직접 확인해야 하는 항목**들이다. 여기가 채워지기 전에 Phase 1 코드를 쓰지 않는다. 문서 조사와 실제 동작이 다른 지점이 반드시 나오고, 그 차이가 아키텍처를 바꾼다.

항목은 **35개**다 — A 5 · B 5 · C 8 · D 6 · E 5 · F 6.
각 항목은 확인 후 `결과` 칸에 **날짜와 실측값**을 적는다. "될 것 같다"는 기록하지 않는다.

잴 수 있는 것은 손으로 적지 않는다 — `python scripts/phase0_probe.py` 가 자동으로 재서
[`phase0-results.md`](phase0-results.md) 에 회차별로 남긴다. 키움 항목은 앱키가 있어야
하므로, 없으면 `SKIP` 으로 기록하고 나머지를 계속 잰다. **"키가 없어서 아무것도 못 쟀다"가
아니라 "무엇을 못 쟀는지"가 남아야 한다.**

주문(F)은 자동화하지 않는다. 모의투자라도 주문은 사람이 직접 내는 행위다.

## B. 유량 제한 실측

문서상 국내주식 조회·주문 각 **초당 5회**, 모의투자는 **TR당 초당 1회**. 실제로 어떻게 카운트되는지 확인한다.

| # | 확인 항목 | 방법 | 결과 |
|---|---|---|---|
| B1 | 조회 TR 초당 한도 | 같은 TR을 **동시에** 발사(연결 웜업 + Barrier). 순차로는 RTT 에 막혀 닿지 못한다 | **2026-08-30: 동시 20회 → 통과 10~11 · 나머지 429**(`1700 허용된 API 요청 개수를 초과`). **문서상 초당 5회의 두 배다** |
| B2 | 서로 다른 TR도 합산되는지 | 단일 TR 20회 vs TR 2종 10+10 을 같은 조건에서 비교 | **2026-08-30: 합산되지 않는다 — 버킷이 TR 별로 분리돼 있다.** 단일 11통과 vs 2종 18통과. 서로 다른 TR 병렬은 처리량이 배가되지만 **한 TR 만 쓰는 백필에는 도움이 안 된다** |
| B3 | 한도 초과 시 복구 방식 | 429 를 유발한 뒤 단일 호출로 재시도 | **2026-08-30: 즉시 재개(0.9초 = RTT 1회분).** 차단이 지속되지 않고 **재실행이 필요 없다** — 초과분만 버려진다 |
| B4 | 모의투자 유량이 실제로 TR당 초당 1회인지 | | |
| B5 | 분·시간 단위 누적 한도 존재 여부 | 초당 한도 아래(5회/초)로 지속 발사 | **2026-08-30: 없다.** 1분 300회 전부 통과, 별도로 5분 창 1,250회도 거부 0. **OpenAPI+ 의 분당 100·시간당 1,000 은 REST 에 없다** |
