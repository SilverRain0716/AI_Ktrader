## 2. 반복된 결함 — **한쪽만 배선돼 있다**

이번 주에 나온 결함 일곱 개가 전부 같은 모양이었다. 우연이 아니다.

| | 있던 것 | 없던 것 |
|---|---|---|
| 계좌 분리 | `paper_positions.arm` 컬럼 | 체결이 arm 을 안 따라감 (`apply_fills(arm=1)` 고정) |
| 진입 조건 | 컬럼 5개 | 아무것도 안 채움 → 무효화 감시가 포지션을 통째로 건너뜀 |
| 보유 검사 | "결정에 나온 종목이 보유 중인가" | **그 반대** — 보유 2건이 통째로 빠져도 통과 |
| 팩 | 검증은 arm 별 팩 | 모델에는 arm 1 팩을 보냄 |
| 매도 | `close_position()` | **부르는 사람** |
| 손절선 | `stop_price` 저장 | **읽는 사람** (저장 코드 말고 0줄) |
| flow 채널 | 주석에 실리콘투 사례가 옳게 적힘 | 그 조건이 **필터에는 안 들어감** |

### 왜 이런 모양이 되는가

**스키마·주석·문서를 먼저 쓰고 코드를 나중에 맞추는데, 그 사이가 이어졌는지 확인하는
단계가 없다.** 컬럼이 있으면 채워진다고, 주석에 적혀 있으면 코드가 그렇게 한다고
가정한다. 그리고 **둘 다 겉으로는 구분되지 않는다** — CLAUDE.md 맨 앞 문장 그대로다.

### 잡는 방법

`stop_price` 를 찾을 때 **읽는 쪽이 저장하는 쪽밖에 없다**는 것이 신호였다.
새 필드·새 규칙을 넣을 때 **쓰는 쪽과 읽는 쪽을 함께 세는 습관**이 필요하다.
