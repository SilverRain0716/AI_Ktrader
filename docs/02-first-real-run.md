# 첫 실제 데이터 적재에서 드러난 것

- 날짜: 2026-08-22
- 관련: [설계안 v1](00-design-v1.md) · [컨텍스트 팩 설계](01-context-pack-design.md)

데이터 계층·브리핑 계층·판단 계층을 전부 시드 DB로만 검증한 상태에서, 처음으로 실제 데이터를 적재했다.
**세 개의 버그와 두 개의 설계 오류가 드러났고, 그중 둘은 조용히 잘못 돌아가고 있었다.**

---

## 0. 적재 결과

| 항목 | 수치 |
|---|---|
| 종목 마스터 | 2,764 |
| 일봉 | 316종목 · 83,823행 (2025-07-18 ~ 2026-08-21) |
| 수급 | 200종목 · 4,000행 |
| 지표 | 314종목 |
| 브리핑 | 60건 · 관점 208개 |
| 관리종목 제외 | 161 |
| 컨텍스트 팩 | 유니버스 42 · 14,504 토큰 |

수집 실패는 0건이었다. 네이버·GitLab·DART 모두 클라우드 컨테이너에서 정상 응답했다.

---

## 1. 🔴 코스닥 대장주가 통째로 빠져 있었다

가장 심각한 버그다. **조용히 잘못 돌아가고 있었고, 유니버스는 정상으로 보였다.**

FDR은 시장 구분을 4가지로 준다.

```
KOSPI 942 / KOSDAQ 1772 / KONEX 109 / KOSDAQ GLOBAL 50
```

`KOSDAQ GLOBAL` 은 코스닥 우량주 50종목에 붙는 별도 구분인데, `fetch_listed` 의 필터가
`("KOSPI", "KOSDAQ")` 뿐이라 이 50종목이 종목 마스터에서 통째로 빠졌다.

빠진 종목들:

| 종목 | 시가총액 |
|---|---|
| 알테오젠 | 17.1조 |
| 에코프로비엠 | 10.3조 |
| 주성엔지니어링 | 7.8조 |
| 원익IPS | 5.3조 |

브리핑이 알테오젠에 관점을 부여해도 종목코드 매핑이 실패했고, 유니버스에는 애초에 후보로 오르지 못했다.
**코스닥 스윙 후보의 상당 부분이 시야 밖에 있었던 셈이다.**

→ `KOSDAQ GLOBAL` 을 포함하고 저장 시 `KOSDAQ` 으로 정규화한다(스키마의 market enum이 KOSPI|KOSDAQ).
KONEX는 유동성이 낮아 계속 제외한다. 회귀 테스트로 고정했다.

## 2. 🔴 섹터 컬럼이 섹터가 아니었다

FDR `KRX-DESC` 의 `Sector` 컬럼에 들어 있는 값:

```
벤처기업부 · 중견기업부 · 우량기업부 · 기술성장기업부
관리종목(소속부없음) · SPAC(소속부없음) · 투자주의환기종목(소속부없음) · 외국기업(소속부없음)
```

**이건 업종이 아니라 코스닥 소속부다.** 진짜 업종분류는 `Industry` 쪽에 있다.
섹터 집중도 한도(`max_weight_pct_per_sector`)가 이 값으로 판정되고 있었으므로 완전히 무의미했다.

그런데 `Industry` 도 그대로는 못 쓴다 — 한국표준산업분류라 **158개로 잘게 쪼개져 있고,
1종목뿐인 업종이 22개, 5종목 이하가 73개다.** 반도체 두 종목이 '반도체 제조업'과 '전자부품 제조업'으로
갈리면 집중도 한도에 걸리지 않는다.

→ 키워드 매핑으로 **14개 대분류**를 파생했다(`sector_group`). 실측 분포:

```
기타 378 · 기계·장비 312 · 제약·바이오 259 · 반도체·전자 242 · IT·소프트웨어 228
화학 222 · 유통·소비재 204 · 금융 155 · 자동차 116 · 통신·미디어 111
철강·금속 105 · 건설·부동산 87 · 에너지·유틸리티 54 · 운송·물류 30 · 조선·방산·항공 27
```

'기타' 378개는 개선 여지가 있다(업종 정보 자체가 없는 113종목 포함).

### 부산물: 관리종목 목록을 얻었다

설계 9장에 "관리종목·투자경고 목록이 없다 — 대체재가 불완전하다"고 남겨둔 구멍이 있었다.
소속부 표시(`관리종목(소속부없음)`, `투자주의환기종목(소속부없음)`)로 **161종목을 걸러낼 수 있게 됐다.**
FDR의 `KRX-ADMINISTRATIVE` 가 깨져 있고 KIND가 해외 IP를 막는 상황에서 유일한 무료 신호다.

## 3. 🔴 NaN 이 truthy 라서 전 종목의 섹터가 NULL 이 됐다

`sector_group()` 의 가드가 `if not industry` 였다. pandas 결측은 `float('nan')` 으로 들어오는데
**NaN 은 truthy 다.** 그래서 가드를 통과한 뒤 `k in industry` 에서 `TypeError` 가 났고,
배치가 죽는 대신 전 종목 `sector_group` 이 NULL 로 적재됐다.

→ `isinstance(industry, str)` 로 바꿨다.

## 4. 🟡 브리핑 형식이 또 바뀌었다 (여섯 번째 변형)

2026-08-21 브리핑부터 `관점:` 라벨이 사라지고 헤더 줄에 직접 붙는다.

```
1. 삼성전자(005930) 281,500원 +3.78% — 주목/확신도 중상
```

기존 파서는 "관점"이라는 단어를 요구했으므로 **3개 브리핑의 관점이 통째로 누락**됐다
(8/21 kr-close-deep, 8/21·8/22 us-close).

→ 구분선(—) 뒤에 오고 `/확신도` 가 따라오는 경우로 한정해 인식한다.
라벨 없이 관점 단어만으로 매칭하면 복기 문장('SK하이닉스 주목(중상) → +12.73%')까지 잡히기 때문이다.
수정 후 관점이 **175 → 208개(+33)** 로 늘었다.

**이건 일회성 수정으로 끝날 문제가 아니다.** 브리핑 형식이 6번 바뀌는 동안 파서는 매번 뒤따라갔다.
근본 해결은 브리핑 생성 시점에 JSON을 함께 출력하는 것이다 — 파싱을 없애는 쪽이 맞다.

---

## 5. 🟡 컨텍스트 팩이 설계 예산의 1.6배였다

설계는 유니버스 60종목에 종목당 70토큰, 팩 전체 11,000토큰을 예상했다.
실제로는 **종목당 313토큰**이었다. 원인은 둘.

- **과도한 소수점** — `1167933.3333`, `9.5429`, `14192.7204`. AI 판단에 소수점 4자리는 아무 의미가 없고 주의만 분산시킨다.
- **중복 필드** — `ma5`/`ma20`/`ma60` 원값. `ma_aligned`(정배열)와 `disparity20_pct`(이격도)가 있으면 불필요하다.

→ 가격은 정수, 비율은 소수점 둘째 자리로 반올림하고 이동평균 원값·null·빈 배열을 뺐다.
**종목당 821자 → 652자, 팩 18,050 → 13,335토큰.** 60종목 정원을 채워도 약 17,700토큰으로 상한 안이다.

추가로, 36시간 창에 같은 종류의 브리핑이 이틀치 들어오던 것을 **종류별 최신 1건**으로 제한했다.
낡은 쪽은 토큰만 먹고 어느 것이 최신인지 헷갈리게 한다.

## 6. ✅ 기우였던 것: 하드 필터 임계값

거래대금 100억 / 시총 3,000억이 너무 좁아 코스닥 중소형주가 다 빠질 것을 우려했다.
실측은 다르다.

| 임계값 | 통과 (시총 상위 300 기준) |
|---|---|
| 거래대금 100억 / 시총 3,000억 | **192** |
| 거래대금 50억 / 시총 1,000억 | 233 |
| 거래대금 30억 / 시총 500억 | 263 |

탈락은 거의 전부 거래대금 미달이었고 시총 조건은 사실상 걸리지 않았다.
전 종목 기준 하드 필터 후보는 **637종목**이다. 3채널 랭킹이 무의미해지는 임계(150)를 크게 웃돈다.

## 7. 남은 것

- **수급 채널이 200종목 분량만 적재됐다.** 전 종목으로 넓히려면 배치 시간이 종목당 약 1.3초 필요하다.
- **`daily-economy` 는 관점이 0이다.** 시장 배경만 제공하므로 정상이지만, 팩에서 차지하는 토큰 대비 가치를 재봐야 한다.
- **미매핑 관점 2건** — `LS전기`(정식명 LS ELECTRIC), `삼성생명·보험주`(복합 표현). 브리핑이 정식 종목명을 쓰지 않는 경우다.
- **분봉은 여전히 없다.** 키움 REST 승인 전까지 적재를 시작할 수 없다.

---

## 8. 이번 실행이 말해주는 것

시드 DB 테스트는 **로직의 정합성**을 검증하지만 **전제의 정확성**은 검증하지 못한다.
`KOSDAQ GLOBAL`, `Sector` 컬럼의 정체, NaN 의 truthiness — 셋 다 테스트를 100% 통과한 코드에서 나왔다.

앞으로 새 외부 데이터 소스를 붙일 때는 **적재 직후 분포를 눈으로 확인하는 단계**를 반드시 넣는다.
"실패 0건"은 데이터가 옳다는 뜻이 아니다.
