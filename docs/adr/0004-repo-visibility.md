# ADR 0004 — 저장소를 당분간 public으로 두되, 전환을 기계가 강제한다

- 상태: 채택
- 날짜: 2026-08-20
- 관련: [README 보안 규칙](../../README.md)

## 맥락

초기 방침은 "이 저장소는 private이며 앞으로도 private이다"였다. 이후 협업 편의상 public으로 전환했다.
전환 시점에 커밋 히스토리 전체를 스캔한 결과 **실제 키·토큰·계좌번호는 유출되지 않았다** (검사 항목: GitLab PAT,
텔레그램 봇 토큰, DART 키, GitHub PAT, AWS 키, 개인키, 계좌번호 패턴, `.env` 추적 여부).

## 결정

**설계·데이터 계층 단계까지는 public을 유지한다. 단, 전환 시점을 사람의 기억이 아니라 CI가 강제한다.**

## 근거

public의 실익:
- GitHub 시크릿 스캐닝과 푸시 보호가 무료로 적용된다 (private은 GHAS 유료 필요).
- 외부 도구·에이전트가 읽기 접근을 별도 설정 없이 얻는다.

public의 위험 — 그리고 그 위험이 **언제** 실체화되는지:
- public 저장소의 push 이벤트는 실시간으로 스크래핑된다. 키가 박힌 커밋은 수 분 내에 수집되며,
  커밋을 되돌려도 히스토리·포크·캐시가 남아 **키 전면 교체 외에는 대응 수단이 없다.**
- 그런데 지금 저장소에는 계좌에 접근하는 코드가 **없다.** 데이터 수집과 지표 계산뿐이다.
  즉 현재 시점의 실제 위험은 낮고, 위험은 특정 지점에서 급격히 올라간다.

따라서 "언제 private으로 바꿀 것인가"를 문장이 아니라 **검사 조건**으로 못박는다.

## 전환 트리거 (CI가 검사한다)

`.github/workflows/repo-guard.yml`이 아래 조건에서 빌드를 실패시킨다.

1. **`execution/` 에 코드가 들어오는 순간** — 주문 경로가 열리는 지점이다.
2. **`EXECUTION_MODE=live` 또는 `KIWOOM_ENV=real` 이 커밋되는 순간.**

추가로 매주 월요일 스케줄 실행으로 상태를 다시 확인한다. 잊고 지나가는 것을 막기 위해서다.

조건식 정의(`docs/condition-definitions.md`)가 채워지면 경고만 낸다 — 전략 노출은 자금 노출과 성격이 다르고,
차단할 만큼은 아니라고 판단했다.

## 감수하는 비용

- 전략 로직과 스크리닝 규칙이 공개된다. 엣지의 일부를 포기하는 것이다.
- `constraints`에 들어갈 운용 자금 규모·리스크 한도는 **저장소에 커밋하지 않고 환경변수로만** 주입한다.
  이 부분은 public 여부와 무관하게 지켜야 한다.

## 재검토 조건

- 위 트리거 중 하나라도 발동하면 즉시 private 전환. 이 ADR은 그 시점에 폐기하고 새 ADR로 대체한다.
