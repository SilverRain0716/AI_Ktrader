# ADR 0003 — AI는 파이프라인의 마지막에서 종합 판단한다

- 상태: 채택
- 날짜: 2026-08-20
- 관련: [설계안 v1](../00-design-v1.md) 4장

## 맥락

초기 설계안은 이런 순서였다.

```
브리핑에서 '주목' 종목 추출 → 정량 조건으로 진입 타이밍 확인 → 진입
```

이 구조에서 AI(브리핑)는 **후보 생성기**이고, 실제 실행 판단은 고정 규칙이 한다.

## 문제

1. **보유 중 판단이 불가능하다.** "어제 진입한 A에 오늘 악재 공시가 났다"는 상황에서, 규칙 기반 청산은 손절선 도달 여부만 본다. 악재의 성격과 포지션 전체 맥락을 읽지 못한다.
2. **포트폴리오 수준 판단이 불가능하다.** "B를 사려면 C를 먼저 줄여야 한다", "이미 반도체 비중이 한도에 가까우니 D는 건너뛴다" 같은 결정을 내릴 주체가 없다.
3. **정량과 브리핑이 충돌할 때 조정할 곳이 없다.** 지표는 양호한데 브리핑이 섹터 역풍을 지적하는 경우, 필터 구조에서는 둘 중 하나를 기계적으로 우선할 수밖에 없다.
4. **AI가 자기 판단의 결과를 학습할 수 없다.** 후보만 던지고 나면 그 후보가 어떻게 됐는지 다음 판단에 반영되지 않는다.

## 결정

**순서를 뒤집는다.**

```
정량 지표 + 브리핑 + 계좌·포지션 상태 → 컨텍스트 팩 → AI 종합 판단 → 검증 게이트 → 주문
```

AI가 보는 것은 "후보 목록"이 아니라 **시장 상태 + 포트폴리오 전체**다. 출력은 매수·추가매수·유지·축소·청산을 한 번에 담은 결정 JSON이다.

## 설계 원칙

1. **AI는 컨텍스트 팩 밖의 상태를 알지 못한다.** 여기 없는 정보는 판단에 반영되지 않는다. 따라서 컨텍스트 팩 스키마가 곧 AI의 세계다.
2. **신규 진입은 `universe` 배열 안에서만 고를 수 있다.** 정량 스크리닝을 통과하고 거래 가능한 종목만 들어온다. 종목코드 환각을 구조적으로 차단한다.
3. **`abstain`을 반드시 허용한다.** "오늘은 진입할 만한 것이 없다"고 말할 수 있어야 한다. N개를 채우게 강제하면 근거 없는 종목으로 자리를 메운다.
4. **`invalidation`(무효화 조건)을 필수로 받는다.** 반증 가능한 단일 사건이어야 하고, 실행 계층이 이를 감시 조건으로 등록한다. 충족되면 이벤트 재판단을 트리거한다.
5. **AI 출력은 제안이지 명령이 아니다.** 검증 게이트가 스키마·종목 실재·거래 가능성·비중·손실 한도·유동성·멱등성을 재검증한다. 통과하지 못하면 주문이 나가지 않는다.

## 판단 주기

정기 4회 + 이벤트 트리거. 기존 브리핑 6종의 시각에 맞춘다.

| 시각 | 사이클 | 내용 |
|---|---|---|
| 08:20 | premarket | 브리핑(08:00) 직후. 오늘의 진입·보유 방침 |
| 12:20 | midday | 브리핑(12:00) 직후. 오전 흐름 반영, 보유 점검 |
| 15:00 | preclose | 브리핑(14:50) 직후. 오버나이트 보유 여부 |
| 18:30 | postmarket | 브리핑(18:00) 직후. 복기 및 다음날 관점 |
| 수시 | event | 무효화 조건 충족, VI, 손절선 접근, 급락 |

장중 상시 호출은 비용·지연·일관성 모두에서 불리하다.

## 감수하는 비용

- **판단 지연.** 정기 4회 구조에서는 장중 급변에 즉각 반응하지 못한다. 이벤트 트리거와 실행 계층의 기계적 손절(HARD-STOP)로 보완한다.
- **비결정성.** 같은 입력에 다른 출력이 나올 수 있다. `decision_id`와 컨텍스트 팩을 함께 저장해 사후 재현·감사를 가능하게 한다.
- **비용.** 컨텍스트 팩이 커질수록 호출 비용이 오른다. `universe` 크기 상한을 두고, 지표는 필요한 것만 담는다.

## 재검토 조건

- Phase 5 페이퍼 테스트에서 AI 판단이 정량 베이스라인(Phase 3 백테스트)을 유의미하게 넘지 못하면, AI의 역할을 축소하고 규칙 비중을 늘린다.
