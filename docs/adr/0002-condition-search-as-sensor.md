# ADR 0002 — 키움 조건검색식은 정량 레이어의 본체가 아니라 보조 센서다

- 상태: 채택
- 날짜: 2026-08-20
- 관련: [설계안 v1](../00-design-v1.md) 1장

## 맥락

키움 조건검색식을 정량 스크리닝 레이어로 쓸 수 있는지가 초기 설계의 갈림길이었다. 조건식을 본체로 쓰면 지표 계산과 데이터 수집이 전부 불필요해지므로 개발 비용이 크게 줄어든다. 실제로 초기 논의에서 이 안이 "즉시 가능"으로 제시됐으나, 조건식의 실제 능력을 확인하지 않은 상태의 권고였다.

## 조사 결과

조건식이 **할 수 있는 것**은 넓다. 6개 대분류(범위지정/시세분석/기술적분석/패턴분석/재무분석/순위분석)에 걸쳐 MACD·RSI·볼린저·일목균형표 등 주요 기술 지표, 외국인·기관·연기금 순매수, 프로그램매매, 공매도, 대차잔고, PER/PBR/ROE/영업이익증감률까지 다룬다. AND/OR/NOT과 괄호 중첩도 된다. 국내 증권사 중 최상위권이다.

문제는 **구조적 제약**이다.

| 제약 | 근거 |
|---|---|
| 조건식 생성·수정이 **영웅문4(Windows HTS)에서만** 가능 | 키움 공식: *"조건검색은 영웅문4에서 만드실 수 있습니다."* API로 생성·수정·정의 조회 모두 불가 |
| **최소 판정 주기 1분** | 공식 FAQ: *"조건식에서는 최소 주기가 1분 단위"* |
| **재무는 최근 결산·최근 분기만** | 공식 FAQ: *"이전 기간에 대한 조건식을 설정할 수 없습니다"* → 흑자전환·연속 개선 조건 불가 |
| 실시간 등록 **세션당 10건** | 공식 유량 문서 |
| **결과 100종목 초과 시 실시간 신호 자체가 중단** | OpenAPI+ 개발가이드 |
| 당일 투자자 수급은 **장 종료 후** 제공 | 공식 FAQ → 장중 수급 필터 불가 |
| 조건만족시간이 **재편입 시 최초 시각을 덮어씀** | 공식 FAQ → 이벤트 이력을 신뢰할 수 없음 |
| **백테스트 불가** | 과거 시점의 조건 만족 여부를 재현할 수단이 없음 |

## 결정

**정량 계산은 클라우드에서 자체 수행한다. 조건식은 장중 이벤트 감지 센서로만 보조 사용한다.**

## 근거

세 가지 제약이 결정적이다.

1. **코드로 버전관리·파라미터 스윕이 불가능하다.** 조건식의 정의를 API로 읽을 수조차 없으므로, 시스템의 뼈대가 저장소 밖의 블랙박스가 된다. 성과가 나빠졌을 때 "조건식을 언제 어떻게 바꿨는지"를 추적할 수 없다.
2. **백테스트가 불가능하다.** 정량 뼈대의 기대 수익·최대낙폭을 사전에 알 수 없다면, AI 판단이 기여한 부분을 분리할 수 없다.
3. **재무 조건이 최근 1기로 제한된다.** 스윙 매매의 상당수 아이디어가 "개선 추세"에 기반하는데 이를 표현할 수 없다.

다만 조건식이 **유일하게 잘하는 일**이 하나 있다 — 전 종목 1분 단위 재계산을 키움 서버가 대신해주고, 조건 만족 순간 WebSocket으로 밀어준다. 자체 인프라로 이걸 흉내내려면 전 종목 실시간 시세 구독이 필요한데 세션당 200종목 제한에 걸린다.

따라서 **광의의 조건식 소수(예: 거래대금 급증, 신고가 돌파) 를 이벤트 센서로 등록**하고, 편입 신호를 컨텍스트 팩의 `condition_search_hits`로 넘겨 AI 판단의 입력 중 하나로 쓴다. 진입 트리거로 직결하지 않는다.

## 감수하는 비용

- 데이터 수집·지표 계산 파이프라인을 직접 구축해야 한다 (Phase 1).
- 조건식을 쓰는 만큼 영웅문4 접근이 필요하고, 조건식 정의를 **저장소에 수기로 미러링**해야 한다. `docs/condition-definitions.md`에 조건식별 구성을 기록하고, 변경 시 커밋한다.

## 재검토 조건

- Phase 0의 C5(편입 신호 지연) 측정 결과가 나쁘면 센서 용도조차 폐기한다.
