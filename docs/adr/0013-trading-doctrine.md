# ADR 0013 — 매매 원칙: 무엇을 근거로 사고 파는가

- 상태: 채택
- 날짜: 2026-08-31
- 관련: [ADR 0005](0005-backtest-scope.md), [ADR 0006](0006-edge-hypothesis.md), [ADR 0009](0009-entry-timing.md), [ADR 0010](0010-news-and-context.md), [ADR 0011](0011-event-scan.md), [ADR 0012](0012-news-channel.md)

## 맥락

지금까지의 ADR 은 **구조**를 정했다 — 무엇을 측정하고(0005·0006), 언제 들어가고(0009), 무엇을 컨텍스트로 보고(0010·0012), 급변을 어떻게 정의하는가(0011).

**"무엇을 근거로 사고 파는가"는 한 번도 적히지 않았다.** 채널 정의(momentum·flow·briefing)가 사실상 그 역할을 했는데, 그것은 *구현된 것*이지 *의도된 것*이 아니다. 둘의 차이가 드러난 것이 SK이노베이션 사례다 — 세 채널 모두 **이미 형성된 상태**만 보았고, 아무도 그것을 의도하지 않았다.

이 ADR 은 사장님이 제시한 매매 원칙을 **정본으로 못 박고**, 지금 시스템과 어디가 맞고 어디가 어긋나는지 대조한다.

---

## 원칙

> **1. 증거금 20~40% 인 우량주만 거래한다.**
>
> **2. 익절·손절은 % 로 계산하지 않는다.** 수급과 이슈, **재료의 소멸**로 판단한다.
>
> **3. 매수의 가장 큰 요인은 이슈의 파급력이다.**
> - 섹터 전반에 장기적 긍정 요소가 가해지는 것이 **가장 바람직한 매수 관점**이다
> - 개별 이슈(갑작스런 큰 실적·수주)는 **하루 이틀 정도** 가져갈 종목이다
>
> **4. 매도의 가장 큰 요인은 악재 발생이다.**
> - 시장 전체에 악영향을 미칠 이슈(금리 인상, 전쟁 발발 등)가 가장 크다
> - **단 그때 수급이 들어오는 종목은 저점 매수의 기회다**
> - 유상증자·계약 취소 등은 개별 악재다
>
> **5. 거래대금과 수급 주체 파악이 분석의 기초다.**
> - 거래대금이 **늘면서** 외국인·기관이 계속 매집 → **매수 이유를 찾아야 한다**
> - 거래대금이 **줄면서** 외국인·기관이 계속 매집 → 눌림인지 하락 전환인지 살펴야 한다

## 시스템 대조

| 원칙 | 지금 상태 |
|---|---|
| 1. 우량주 필터 | **데이터가 없다** |
| 2. 재료 소멸로 청산 | 스키마에 `invalidation` 이 **있는데 감시 코드가 0줄** |
| 3. 파급력 · 섹터 vs 개별 | [ADR 0012](0012-news-channel.md) 의 `scope` 와 맞물린다 |
| 4. 시장 악재 시 저점 매수 | **CLAUDE.md 와 충돌한다** |
| 5. 거래대금 × 수급 | flow 채널이 **거래대금 방향을 안 본다** |

## 결정

### 1. 우량주 필터 — 증거금률을 구하지 못했다. 프록시로 대신하되 **같다고 말하지 않는다**

증거금률은 거래소 값이 아니라 **증권사가 종목별로 정하는 값**이라 시세 API 에 없다. 실제로 찾아봤고 전부 막혔다.

| 시도 | 결과 |
|---|---|
| 키움 `ka10001` (45개 필드) | 증거금률 없음. `crd_rt` 가 있으나 **신용비율**이지 증거금률이 아니다 |
| 네이버 종목 메인·시세·종목분석 | `증거금` 문자열 **0회** |
| 키움 증거금률 안내 페이지 | HTTP 200 이나 `증거금` **0회** (JS 렌더로 추정) |

**당장은 이미 가진 값으로 대신한다** — 시가총액 · 20일 평균거래대금 · 관리종목 여부. 다만 **이것이 증거금률과 얼마나 일치하는지 모른다.** 증거금률은 증권사의 위험 평가이고 시총은 크기일 뿐이라, 겹치지만 같지 않다.

**"우량주 필터를 넣었다"고 말하지 않는다.** 프록시라고 적고, 증거금률표를 확보하면 교체한다.

### 2. `stop` 은 남기고, 청산 판단은 `invalidation` 이 한다

원칙 2 를 *"손절선을 없앤다"* 로 읽으면 안 된다. **포지션 크기가 손절폭에서 나오기 때문이다.**

```
포지션 크기 = 계좌 × 1회손실한도 ÷ 손절폭
```

손절폭이 없으면 **얼마를 살지 정할 수 없다.** 그래서 역할을 나눈다.

| | 역할 | 기준 |
|---|---|---|
| **`invalidation`** | **주 청산 판단** | 수급 이탈 · 재료 소멸 — 원칙 2 가 말하는 것 |
| `stop` | 재난 방지선 · **포지션 크기 산출 근거** | 2 ATR ([ADR 0009](0009-entry-timing.md)) |

`stop` 은 평소에 닿지 않는 값이어야 한다. 닿는다면 `invalidation` 이 먼저 작동했어야 하는데 못 한 것이다 — **그 빈도 자체가 `invalidation` 설계의 품질 지표다.**

**감시기를 만들었다**(2026-08-31, `decision/invalidation.py` · `python -m decision.pipeline watch`).

만들면서 **enum 자체가 원칙 2 를 담지 못한다**는 것을 발견했다. 다섯 값 중 둘이 가격 기준이고 **수급 타입이 하나도 없었다** — 그대로 감시기를 만들었으면 원칙 2 가 아니라 가격 손절을 감시하게 된다. 두 타입을 추가했다.

| type | 무엇이 재료 소멸인가 | value |
|---|---|---|
| **`flow_reversal`** | **외국인·기관이 함께 순매도**로 도는 것 | 연속 일수 |
| **`volume_dryup`** | 거래대금이 20일 평균 아래로 식는 것 | 배수(0~1) |

한쪽만 파는 것은 흔해서 **양쪽이 함께 돌 때만** 본다 — 한쪽 기준이면 거의 매일 참이 된다.

**판정할 수 없으면 `UNKNOWN` 이지 `SAFE` 가 아니다.** 빈 테이블 조회가 조용히 통과했던 악재공시 필터와 같은 사고를 막는다. 판정불가가 절반을 넘으면 경고한다 — **감시하는 척만 하는 상태**를 드러내기 위해서다.

**감시기는 청산하지 않는다.** 실행 계층이 0줄이라 여기서 포지션을 닫으면 킬 스위치도 멱등성도 없는 자리에서 상태를 바꾸는 것이 된다. `invalidation_hit` 만 찍고 재판단(event 사이클)에 넘긴다.

**아직 감시되지 않는 것**: `stance_reversal`(브리핑 관점 반전 판정기가 없다)과 `unstructured`. 그리고 **뉴스 기반 재료 소멸은 수집 자체가 없다**([ADR 0012](0012-news-channel.md)).

### 3. `scope` 가 보유기간을 정한다 — 참고값에서 결정 변수로 올린다

[ADR 0012](0012-news-channel.md) 는 `scope`(stock / sector / market)를 *"가격과 대조하는 용도이지 단독 근거가 아니다"* 로 두었다. 원칙 3 이 여기에 **의미를 준다.**

| `scope` | 보유 | 원칙 3 |
|---|---|---|
| `sector` | **길게** | 가장 바람직한 매수 관점 |
| `stock` | **1~2일** | 짧게 가져갈 종목 |
| `market` | 후보 아님 | 개별 매수 근거가 아니다 |

`max_hold_days` 에 직접 연결된다. **다만 "길게"가 며칠인지는 정하지 않는다** — [ADR 0009](0009-entry-timing.md)·[0011](0011-event-scan.md) 에서 고정값을 두 번 틀렸다. 실험이 정한다.

**`scope=sector` 는 뉴스 판정만으로 확정하지 않는다.** [ADR 0012](0012-news-channel.md) 결정 5 대로 **가격이 정본**이다 — 같은 업종 종목들의 당일 등락을 ATR 로 정규화해 실제로 동반 상승했는지 본다. AI 의 `scope` 판정과 어긋나면 **가격을 따른다.**

### 4. 시장 악재 시 저점 매수 — **재량이 아니라 규칙이다.** CLAUDE.md 를 정정한다

지금 CLAUDE.md 에 이렇게 적혀 있다.

> *"오늘 시장이 빠지니 관망"은 규율이 아니라 재량이다. 하루 지수 하락은 stop 안에서 소화된다.*

원칙 4 는 그 반대를 말하는 것처럼 보이지만 **아니다.** 저 문장이 막으려던 것은 *"무서우니까 안 산다"* 는 **근거 없는 회피**다. 원칙 4 는 근거를 준다.

```
sign = negative  AND  scope = market  AND  외국인·기관 순매수 > 0  →  저점 매수 후보
```

**세 항목 모두 우리가 가진 값이다.** 기계가 판정할 수 있으면 재량이 아니다. CLAUDE.md 의 문장은 **유지하되**, "시장 악재 자체는 관망의 근거가 아니며, 그때 수급이 들어오는 종목은 오히려 후보다"를 덧붙인다.

원칙 4 의 개별 악재(유상증자·계약 취소)는 **이미 잡고 있다** — `disclosures` 의 `disqualifying`, 그리고 [ADR 0012](0012-news-channel.md) 판정의 `sign=negative`. 실측 사례가 있다: 삼성바이오로직스 3조 유상증자, 그날 −6%.

### 5. flow 채널에 **거래대금 방향** 축을 넣는다

지금 flow 채널은 *"외인 또는 기관 3일 연속 + 5일 순매수 > 0"* 만 본다. **거래대금이 느는지 주는지 안 본다.** 그래서 원칙 5 의 두 상태를 구분하지 못한다.

| 거래대금 | 수급 | 뜻 | 지금 |
|---|---|---|---|
| **증가** | 매집 | **매수 이유를 찾아야 한다** | 구분 못 함 |
| **감소** | 매집 | 눌림인지 하락 전환인지 | 구분 못 함 |

**"매수 이유를 찾아야 한다"가 곧 뉴스 조회다.** 원칙 5 가 [ADR 0011](0011-event-scan.md) 급변 스캔과 [ADR 0012](0012-news-channel.md) 뉴스 채널을 하나로 잇는다.

```
거래대금 증가 + 매집  →  뉴스 조회  →  파급도 판정  →  후보
```

이는 [ADR 0011](0011-event-scan.md) 의 결정을 **바꾸지 않는다.** 급변 스캔은 여전히 후보를 만들지 않고, **뉴스 조회 대상을 정하는 데** 쓰인다 — 0011 이 *"급변 종목의 뉴스를 매일 수집·보존"* 으로 이미 적어둔 그 일이다.

거래대금 방향도 **ATR·배수와 같은 이유로 절대량이 아니라 배수**로 잡는다([ADR 0011](0011-event-scan.md) `volume_multiple`). 임계는 정하지 않는다.

## ADR 0006 과의 관계 — 이 원칙은 **선택**이지 규율이 아니다

[ADR 0006](0006-edge-hypothesis.md) 이 엣지를 둘로 갈랐다. **1차 = 규율(봉투)**, **2차 = 선택.**

**이 ADR 의 다섯 원칙은 대부분 2차 엣지, 즉 선택의 내용이다.** 무엇을 근거로 고르는가에 대한 사장님의 관점이고, F2 가 재려는 대상이 바로 그것이다.

예외가 둘이다. **원칙 1(우량주 필터)은 유니버스 구성**이므로 봉투에 가깝고, **원칙 2의 `stop`** 은 [ADR 0009](0009-entry-timing.md) 가 이미 봉투로 못 박았다. 이 둘은 전 arm 공통으로 기계가 강제한다.

**나머지 셋(파급력·악재·수급×거래대금)은 AI 가 판단한다.** 프롬프트에 원칙으로 싣고, 성적은 F2 가 잰다. **원칙이 옳다는 것을 전제하지 않는다** — 사장님의 관점을 명시적으로 넣고, 그것이 정량 랭킹(Arm 0)보다 나은지를 재는 것이 이 시스템의 목적이다.

## 감수하는 비용

- **우량주 필터가 프록시다.** 증거금률과 다른 종목이 섞이거나 빠진다. 얼마나 다른지 **모른다**
- **원칙 2 가 절반만 작동한다.** 수급·거래대금·공시는 감시되지만 **뉴스 기반 재료 소멸은 수집 자체가 없고**, `stance_reversal` 은 판정기가 없다. 그리고 **감시기는 표시만 하고 청산하지 않는다** — 실행 계층이 생기기 전까지 실제 청산은 여전히 `stop` 과 `max_hold_days` 다
- **원칙 3 의 "길게"가 미정이다.** `scope=sector` 후보가 나와도 며칠 들 것인지 정해지지 않았다
- **채널이 늘어난다.** 거래대금 방향 축 추가 + 뉴스 채널([ADR 0012](0012-news-channel.md))로 F2 표본이 두 번 갈린다. 채널 변경 시점을 기록하고 구간을 끊어서 잰다
- **원칙을 프롬프트에 실으면 AI 가 그것을 사후 정당화할 수 있다.** "파급력이 크다고 판단했다"는 근거 없이도 쓸 수 있는 말이다 — `scale_raw` 를 제목의 부분문자열로 강제하는 것([ADR 0012](0012-news-channel.md))과 같은 검산 장치가 다른 필드에도 필요하다

## 재검토 조건

- **증거금률표를 확보하면** 프록시를 교체하고, 프록시가 얼마나 틀렸는지 소급해서 잰다
- **`stop` 도달 빈도가 높으면** `invalidation` 설계가 잘못된 것이다 — 재료 소멸을 못 잡고 있다는 뜻이다
- **`scope=sector` 판정과 가격의 섹터 동반 상승이 자주 어긋나면** AI 의 `scope` 를 버리고 가격만 쓴다
- F2 가 원칙 기반 선택이 정량 랭킹보다 못하다고 말하면 **원칙을 다시 본다** — 그것이 이 시스템을 만드는 이유다

## 확인하지 못한 것

- **증거금률을 어디서 받는가.** 세 경로가 막혔다. 키움 HTS·영업점 자료가 남았으나 자동 수집 가능한지 모른다
- **시총·거래대금 프록시가 증거금률과 얼마나 겹치는가.** 정답표가 없어 지금은 잴 수 없다
- **"재료의 소멸"을 기계가 어떻게 판정하는가.** 원칙은 명확하지만 조건식은 아직 없다 — `invalidation` 감시기를 만들 때 정해야 하고, 이것이 이 ADR 에서 가장 어려운 부분이다
- **섹터 재료의 지속 기간 분포.** 원칙 3 이 "길게"라고 했지만 실제로 며칠인지 재본 적이 없다
- **시장 악재 시 수급 유입 종목의 성과.** 원칙 4 의 저점 매수가 실제로 유효한지 소급 검증하지 않았다 — 수급 12개월 백필이 방금 끝났으므로(664종목 260거래일) **이제 잴 수 있다**
