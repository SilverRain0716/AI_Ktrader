# ADR 0001 — 키움 REST API 위에 신규 구축한다

- 상태: 채택
- 날짜: 2026-08-20
- 관련: [설계안 v1](../00-design-v1.md) 2장

## 맥락

기존 K-Trader는 키움 OpenAPI+(32비트 COM/OCX, PyQt5) 기반이다. 3년치 실전 디버깅이 녹아 있어 재활용 가치가 있으나, AI 판단 중심 시스템의 토대로 쓸 수 있는지 판단해야 했다.

## 검토한 선택지

1. **OpenAPI+ 유지 + AI 계층 추가** — 기존 자산 최대 활용
2. **키움 REST API로 신규 구축**
3. **한국투자증권 KIS API로 신규 구축**
4. **LS증권 OPEN API로 신규 구축**

## 결정

**키움 REST API(2025-03-24 출시)로 신규 구축한다.**

## 근거

### OpenAPI+를 배제한 이유

- **32비트 파이썬이 강제된다.** OCX가 VC++ 2010 32비트로 빌드되어 있다. AI 판단 엔진에 필요한 라이브러리 대부분이 32비트 프로세스에서 동작하지 않는다. 이것 하나로 결론이 난다.
- Windows 전용이며 HTS 로그인 창(GUI)을 띄워야 한다. 클라우드 24시간 무인 운영이 불가능하다.
- 유량이 초당 5 / 분당 100 / 시간당 1,000이며, 분·시간 한도 초과 시 **프로그램 재실행이 필요**하다.

### 키움 REST를 택한 이유

- 키움 공식 문구: *"멀티 OS — 윈도우, 맥, 리눅스 등 다양한 운영체제 이용 가능"*, *"미설치형 — OCX 방식에서 벗어나 설치하지 않고 이용 가능"*
- 과거 차트가 `ka10079~94`로 1:1 대응되며 **연속조회(`cont-yn`/`next-key`)와 수정주가 옵션**을 지원한다.
- **조건검색 실시간 푸시(`ka10173`)를 제공한다.** 한국투자증권은 폴링만 가능하다.
- 유량이 초당 5회로 단순하고 분·시간 누적 한도가 문서에 없다.
- 실시간 시세가 세션당 200종목. KIS는 세션당 41종목이라는 비공식 보고가 있다.

### 다른 증권사를 택하지 않은 이유

- **KIS**: 상품 커버리지(국내 선물옵션, 해외선물, 채권)는 가장 넓으나 조건검색이 폴링뿐이고 WebSocket 등록 종목 수가 불리하다. 2026-03-20 자로 신규 고객 초당 호출 제한 공지가 있으나 본문을 확인하지 못했다.
- **LS증권**: 조건검색 연동 API 자체가 없다. 제공되는 `종목검색`은 카테고리 기반 스크리너이지 HTS 사용자 조건식 연동이 아니다.

## 감수하는 비용

- **국내 선물/옵션 미지원.** 키움 REST의 매매 가능 상품은 국내주식·미국주식(+KRX 금현물)이다. 파생 전략이 필요해지면 KIS 병행 또는 OpenAPI+ 잔존이 필요하다. 현재 목표가 주식 스윙이므로 수용한다.
- **조건식 생성은 여전히 영웅문4(Windows) 필요.** 단 만들 때만이고 런타임 상주는 불필요하다.
- **모의투자는 KRX만 지원하고 유량이 TR당 초당 1회**로 낮다. 대량 백필은 실전 계좌로 해야 한다.
- **3개월간 실서버 미접속 시 서비스 자동 해지.** 모의투자만 쓰는 개발 기간이 길어지면 해지된다. 주기적으로 실서버 조회를 걸어둔다.

## 재검토 조건

- Phase 0의 A5(리눅스 동작), B3(유량 초과 복구), C2/C3(조건검색 제한) 실측 결과가 문서와 크게 다를 경우
- 국내 파생 상품이 전략에 필요해질 경우
